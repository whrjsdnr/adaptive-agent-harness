# 10영업일 개발 계획

## 계획의 기준

이 계획은 문서·구조 작성 이후의 전체 MVP 구현 계획이다. 현재는 D1~D2의 계약·분석과 D3의 Harness 명세·파일 패키징을 구현했다. D3의 실제 Docker 이미지 빌드는 미검증이다. 실제 Agent 입력·Docker 실측·전체 MVP 인수는 후속 작업이다. D1~D10은 착수 후 10영업일이며 주말·해당 팀의 공휴일은 제외한다. 착수일과 휴일 달력이 정해지지 않아 실제 날짜는 지정하지 않는다.

단일 개발 흐름, 단일 Docker 호스트, 기존 Agent 1개, 벤치마크 1종, 목표 프로파일 1개로 검증하는 최소 MVP를 기준으로 한다. 먼저 수직 실행 경로를 만들고, 실측이 확보된 뒤 최적화와 이식 패키지로 확장한다. 성능 개선 자체는 보장할 수 없으며 개선 없음·판정 보류도 근거를 갖춘 유효 결과다.

## 착수 전 선행 조건

- 사용자가 제공하는 기존 Agent 경로·실행 명령·입출력·의존성·기능 테스트를 확보한다. 새 Agent를 만들어 대신하지 않는다.
- 벤치마크 데이터·평가 버전·품질 기준·목표 지표·반복·예산을 확정한다.
- 실제 Docker 호스트, CPU·메모리·가속기 및 실행 권한을 확인한다. 현재 작업 환경에는 Docker CLI가 없다.
- Python 3.12 프로젝트 가상환경에서 의존성을 해결하고 잠금 파일·빌드 가능 여부를 검증한다. 다른 프로젝트의 가상환경을 변경하지 않는다.
- 목표 하드웨어 프로파일과 실행 호스트 프로파일을 별도로 확보한다. 목표 장비가 없으면 해당 장비의 성능 검증을 범위에서 제외하고 미검증으로 기록한다.
- 보안 하부 Agent 팀과 계약 버전·응답 형태·timeout을 합의한다. 서비스가 없으면 계약 테스트까지만 가능하다. 실제 실행을 위한 보안 게이트 또는 명시적인 제한적 로컬 시험 모드를 정한다.
- Agent 코드 변경 승인 주체·기록 방식·승인 범위를 정한다. 승인이 없으면 차단 경로만 검증하고 실제 코드 변경은 하지 않는다.

선행 조건이 늦어지면 독립적인 계약·정적 분석 작업을 진행하되, 실측 단계는 차단으로 기록하고 일정 재산정 사유를 남긴다. 모의 실행으로 일정상 완료를 채우지 않는다.

| D5 | 벤치마크 반복·원시 지표·집계·비교 가능성 | 실측 기준선과 고정 BenchmarkPlan | 워밍업 제외, 최소 3회 실측·기능 및 품질 평가, 단위·null·호스트 추적; 처음부터 끝까지 실행 경로 확보 |

| D7 | 후보 재실행·비교·채택/기각/보류, orchestration 반복 | 제한된 적응형 탐색과 결과 보고서 | 기존 Agent로 실제 후보 비교; 품질 저하·측정 간섭·변동·개선 없음·실패 후보 처리; 기준 구성이 보존됨 |
| D8 | 최소 Scheduler와 보안 하부 Agent 계약 어댑터 | FIFO·자원 예약·취소, 버전 있는 외부 계약 | 동시성 한도·예약 반환·독점 벤치마크·취소 경쟁; allow/deny/needs_review/unavailable·timeout·변경 후 재검토 계약 테스트 |
| D9 | Hardware Porting Lite 패키지, 승인·패치 사본·테스트·롤백 경로 | 호환성 보고·체크섬 패키지, 변경 통제 증거 | FIT/ADAPT_REQUIRED/UNSUPPORTED/UNKNOWN 호환성 표기·비밀 제외·파일 해시; 미승인·stale 거절, 승인된 시험 패치 전후·원복 테스트 |
| D10 | 전체 인수 시나리오·회귀·문서·완료 판정 | 요구사항별 증거 목록·검증된 범위·미검증 보고 | Ruff·pytest·Docker 실제 인수 실행, 원본 해시·예산·로그·패키지 확인; 증거 없는 항목은 완료에서 제외 |

D9의 승인된 패치 시험은 승인자가 검토한 기존 Agent 작업 사본에서만 수행한다. 실제 승인이 없으면 미승인·오래된 승인 차단 테스트만 통과할 수 있고, 적용·롤백의 실제 Agent 검증은 미완료로 남긴다. 외부 보안 서비스가 없으면 어댑터 계약 테스트 결과와 실제 연동 결과를 구분한다.

## 주요 점검 시점

- D3: 환경·입력·Harness 생성의 재현성 점검. Docker 빌드가 불가능하면 후속 실측 일정 조정.
- D5: 기존 Agent 기준선의 실제 실행 증거 점검. 성공 기준선이 없으면 성능 개선 판정 금지.
- D7: 근거 생성 → 실행 → 비교의 반복이 연결되는지 점검. 채택 후보가 없어도 유효한 기각·보류 보고서를 확인.
- D10: [완료 기준](ACCEPTANCE_CRITERIA.md)의 요구사항별 검증 결과로 인수 범위를 결정.

## 의도적으로 확장하지 않는 기능

새 Agent 생성, Agent 유형별 고정 최적화 처방, 분산 Scheduler·자동 스케일링, 보안 판정 엔진, 하드웨어 에뮬레이션, VM, 이미지 교차 실행, 실제 드론 배포, 웹 UI는 이 계획에 포함하지 않는다.

## 매일 남길 기록

변경 파일·요구사항 ID·설계 결정, 실제 실행 명령·도구 버전·결과·exit code, 실측 실행 ID와 산출물 해시, 실패·skip·미실행·차단 사유, 다음 단계의 선행 조건을 기록한다. 계획에 적힌 작업을 완료 상태로 자동 전환하지 않는다.
